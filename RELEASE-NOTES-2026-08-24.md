# Readiness and release hardening — 24 August 2026

This is the current implementation record. It replaces chat-based descriptions of the Course Workshop readiness work; the 20 August notes remain the historical course-content correction record.

## Released changes

- **Course Workshop 0.5.0 / draft schema v2.** Portable drafts now carry a stable draft id, revision, origin, creation time and last-exported time. A trainer can transfer the complete editable state, including embedded media, and identify which checkpoint another copy came from.
- **Safe migration.** Version-1 drafts and raw released packages retain their editable content but return to Draft status. Course review dates, source checked dates and release declarations are cleared because the earlier format cannot establish current review evidence.
- **Interpretable approval.** Final release now requires reviewer and approver names and roles, approval scope, reference and date in addition to the four declarations.
- **Exact-content binding.** `release-record.json` and `validation-report.json` contain the SHA-256 digest of the exact canonical `course-package.json`. The repository inspector recomputes it and rejects detached, altered or incomplete evidence.
- **Safer external data.** Source links must be credential-free HTTPS. Embedded PNG/JPEG/WebP data must match both the declared data-URL type and its binary signature.
- **Retained releases.** Isolated builds keep `exports/<course-id>/releases/<version>/` copies of the standalone and site forms with a hash manifest. Workshop installation retains the exact approval record at `src/courses/<course-id>/releases/<version>.json`.
- **Symmetric course QA.** `src/course-quality-profiles.ts` declares a current depth and applied-practice profile for every maintained course. The combined suite fails if a catalogue course has no profile or falls below it. The JSON QA report now separates observations from failure messages.
- **Curriculum-version choice.** If browser learning data belongs to a different or previously unrecorded course version, the learner chooses whether to keep it or start only that course fresh. Other courses and person-level settings are unaffected.
- **Growth boundary.** The self-contained Workshop build has a 12 MB ceiling. Crossing it stops release and requires an explicit template/media architecture decision.

## Verification boundary

The automated release workflow covers typechecking, combined and isolated builds, both maintained course profiles, browser behaviour, accessibility regressions, Workshop migration and outputs, package hashing, tamper refusal and controlled install/host routes. Exact results are generated by the scripts; documentation deliberately carries no fixed check count.

These controls do not establish subject-matter correctness, teaching effectiveness, approval authority or complete accessibility conformance. Before organisational production use, observe trainers authoring real short and substantial courses, complete applicable manual accessibility/device work, and retain the genuine review evidence identified by each release record.

## Deliberate non-features

- One course per learner export remains the default. Arbitrary multi-course bundle composition is parked.
- PowerPoint parsing is not included merely for completeness. PDF and ordered PNG/JPEG/WebP are the supported browser import route unless trainer research demonstrates a need.
- Portable draft transfer is not live co-authoring or automatic merge.
